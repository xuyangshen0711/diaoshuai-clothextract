# 导入工作台

在 `/import` 先选择资料用途。外部参考资料只处理图片提取与分类；本厂产品工作区位于 `/import?mode=factory`，也可从本厂图库的“管理本厂资料与导入”进入。

## 本厂资料

- 图片、款式档案和销量均按本厂款号关联；客户版本仍保留完整大货款号。
- 资料待办实时核对档案、汇总、订单明细和可用图片。仅有销量的款号也会提醒补图和补档案。暂无销量作为可选项，不阻止入库。
- “补图片”会带入款号。文件检查会指出无效文件名、同批重复款号和相同图片。同款新图获得有效 AI 建议后自动替换，识别失败时保留原图和人工标签。
- 表格先预览识别类型、款号关联、数据样本、新增/更新/无变化、异常行与合计差异，再确认入库。选择错误入口仍可按实际识别结果导入。
- 预览之后资料发生更新会要求重新预览，避免覆盖刚导入的数据。同一个确认请求重复提交会返回原结果。
- 表格确认结果持久保存在数据库，图片处理沿用可恢复的任务记录。失败任务仅重试未完成项。

## 销量口径

同一客户版本的订单明细优先于未标注范围的汇总，原汇总保留用于核对，不重复累加。此规则也适用于升级前已导入的汇总；数据库中的原始行不会被删除。

常规汇总中相同大货款号、颜色、尺码的行在文件内合并；重复导入会更新原汇总。常规汇总不适合分多张增量表累加。

历史补充需要声明整张表的起止日期并预览该范围。它不能与已有订单日期或其他历史补充交叉；订单缺少日期时也不能确定不重叠。相同范围重复上传按原键更新。后续订单明细进入该范围时，该历史汇总整体转为核对用，避免部分数据重复计数；需要用户补齐该范围的订单明细后再使用完整明细统计。

## 大表导入性能

表格预览只读取 Excel 一次，格式识别、字段解析和异常行检查共用本次读取的内容。
图片完整性仍实时核对；同一预览复用核对结果，OSS 图片以最多 8 个工作线程检查，每个线程复用自己的连接，不跨请求缓存。
商品资料、订单明细和销量汇总按 500 行分批写入，在同一个事务中完成。任何一批失败或实际影响与预览不符时整次导入回滚；相同预览编号重试返回已保存的结果，不会重复累计。
商品资料按完整大货款号更新，查重只查询本批涉及的款号；原有“系列”等范本外字段保留，同一文件重复款号仍采用最后一行。季节多选筛选和订单统计口径保持原规则。
缺少订单金额等必填值的行仍列为异常，不将空金额自动改为零。确认时需明确接受只导入有效行。
若网关等待超时，页面区分预览与确认阶段：预览尚未入库；确认超时则先查看导入记录，也可使用同一预览再次确认。

## 分类与存储

默认自动选择已配置的分类服务。有效 AI 建议直接入库，无需审核。无可用服务或识别失败时，图片留在任务中，修复配置后按批次重试；不计入成功入库。模拟分类仅在高级设置中手动选择，图库明确标记模拟结果。索引和全量重新分类仍保留在高级设置。

图库和详情的「修改标签」按字段保存人工修正，包括主动清空。AI 建议单独保留，重新识别不会覆盖人工修正；可恢复单个字段或全部 AI 建议。文字、图片标签筛选与数据助手采用同一份生效标签，图片外观匹配仍使用原图。

导入页顶部显示 OpenAI、DeepSeek 的密钥配置和最近连接检测结果，导航栏也保留状态入口。“已配置”不代表认证成功：点击“测试连接”才会使用实际分类客户端读取服务商的模型列表（`GET /models`），检查网络与认证，不发送图片或创建分类任务。密钥、服务地址和原始错误均不会返回浏览器。连接结果保留在当前服务进程中 5 分钟，密钥、地址或模型变化后失效；网页刷新状态不会自动请求服务商。模型列表可访问不保证图片分类或账户推理额度可用，仍以实际任务结果为准。

表格预览暂存在 `data/processed/table-previews`，有效期 24 小时；确认结果在 `factory_import_history`。上传、图片、数据库、预览、备份和 `.env` 沿用现有 Git 忽略规则。

## 验证

```sh
.venv/bin/python -m pytest -q tests --ignore-glob='**/._*'
cd frontend
npm run build
```

AppleDouble 文件 `._*` 是外置盘的 macOS 元数据，测试收集时应忽略。MySQL/OSS 的可选集成测试需要对应的独立测试环境。
