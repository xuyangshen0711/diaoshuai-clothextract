# 导入工作台

在 `/import` 先选择资料用途。外部参考资料只处理图片提取与分类；本厂产品工作区位于 `/import?mode=factory`，也可从本厂图库的“管理本厂资料与导入”进入。

## 本厂资料

- 图片、款式档案和销量均按本厂款号关联；客户版本仍保留完整大货款号。
- 资料待办实时核对档案、汇总、订单明细和可用图片。仅有销量的款号也会提醒补图和补档案。暂无销量作为可选项，不阻止入库。
- “补图片”会带入款号。文件检查会指出无效文件名、同批重复款号、相同图片及待审核替换图。
- 表格先预览识别类型、款号关联、数据样本、新增/更新/无变化、异常行与合计差异，再确认入库。选择错误入口仍可按实际识别结果导入。
- 预览之后资料发生更新会要求重新预览，避免覆盖刚导入的数据。同一个确认请求重复提交会返回原结果。
- 表格确认结果持久保存在数据库，图片处理沿用可恢复的任务记录。失败任务仅重试未完成项。

## 销量口径

同一客户版本的订单明细优先于未标注范围的汇总，原汇总保留用于核对，不重复累加。此规则也适用于升级前已导入的汇总；数据库中的原始行不会被删除。

常规汇总中相同大货款号、颜色、尺码的行在文件内合并；重复导入会更新原汇总。常规汇总不适合分多张增量表累加。

历史补充需要声明整张表的起止日期并预览该范围。它不能与已有订单日期或其他历史补充交叉；订单缺少日期时也不能确定不重叠。相同范围重复上传按原键更新。后续订单明细进入该范围时，该历史汇总整体转为核对用，避免部分数据重复计数；需要用户补齐该范围的订单明细后再使用完整明细统计。

## 分类与存储

默认自动选择已配置的分类服务。无可用服务时，图片保存为“待分类”，可直接人工审核或稍后按批次继续分类。模拟分类仅在高级设置中手动选择。索引和全量重新分类仍保留在高级设置。

表格预览暂存在 `data/processed/table-previews`，有效期 24 小时；确认结果在 `factory_import_history`。上传、图片、数据库、预览、备份和 `.env` 沿用现有 Git 忽略规则。

## 验证

```sh
.venv/bin/python -m pytest -q tests --ignore-glob='**/._*'
cd frontend
npm run build
```

AppleDouble 文件 `._*` 是外置盘的 macOS 元数据，测试收集时应忽略。MySQL/OSS 的可选集成测试需要对应的独立测试环境。
