# 图片并行识别和大文件上传

导入任务共用两个图片处理名额。同一批可同时识别两张，多个已抽图批次按图片轮流调度；同一款号或记录保持顺序处理。抽图仍由单独的一个工作线程完成。API 必须保持 `uvicorn --workers 1`，不能用增加进程数扩大并发。

导入页显示全站正在识别和待识别的图片数量、任务批数，以及每批成功、失败和等待数量。还未抽完图的批次数单独提示，待识别总数随抽图更新。运行中的老任务不会因为最近 50 批历史限制而从队列提示中消失。

每张图片的数据库变更和完成检查点在同一事务提交；同一任务的并行完成会串行保存检查点。重试只处理失败和未完成项，已完成项保留。余额、认证、限流异常会停止该批后续派发，已经发出的另一个请求仍可能完成。服务重启将活动任务标为中断，由用户继续，不自动调用收费模型。

新上传流程先通过 `/api/import/uploads` 创建上传会话，按 4 MiB 一块顺序上传，再使用已上传原件检查内容、提交识别。不再在检查和确认阶段重复上传整批文件。现有 Nginx `client_max_body_size 200m` 可以保留；仓库模板的 64m 也能容纳分块请求。

- 单张图片最多 100 MiB（沿用视觉输入上限），文档最多 512 MiB；单批最多 2 GiB、1000 个文件。
- 同一页面的上传失败可继续，服务器返回已收到的字节位置；重复片段不会重复追加。
- 确认提交使用上传会话 ID 作为任务 ID，重复确认不会建立另一个识别任务。
- 未提交暂存文件 24 小时无活动后，在下次创建上传时清理。已入任务的原件不受这个清理规则影响。
- 上传前、每个分块写入前检查磁盘余量，保留至少 1 GiB。关闭页面后需重新选择文件；本版本不承诺跨页面断点续传。
- 图片识别准确率、服务商耗时和收费单价没有改变；并行效果需结合实际任务和服务商状态观察。

验证覆盖：同批两张并行、全局两张上限、新批轮流获得名额、同款号串行与去重、成功检查点不重复调用、210 MiB 文件分块及重传、重复确认、磁盘不足和输入大小边界。

导入体验提示：选中文件后立即检查空文件、单文件大小、批次总大小和数量；超限时标明具体文件并禁止开始上传。达到大小或数量上限的 80% 提醒接近上限；合计达到 200 MiB 提醒耗时较长但仍可上传。上传进度显示当前文件、已传大小和百分比；网络离线、20 秒无新分块进度、上传后检查、暂停续传分别提示，不估算未经测量的剩余时间。

上传中的页面每 20 秒向 `/api/import/uploads/{id}/activity` 发送活动状态，结束时撤销；75 秒没有更新后自动失效。其他页面每 5 秒读取不含本页任务的活动批次数，只提示「另有 N 批文件正在上传」，不推断使用者身份、不展示文件名。状态暂不可用时隐藏提示。该提示沿用单 worker 部署，只用于体验提示，不参与上传准入或 AI 调度。
