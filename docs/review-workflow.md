# 人工审核与 SQLite 存储

## 使用流程

1. 在「导入」上传 PDF、PPTX、Excel，或直接上传图片 / 文件夹。每个文件选择资料大类。抽图、AI 分类完成后即在主页按建议分类展示，并标记「未审核」。卡片显示来源文件类型、文件名、位置和导入时间。本厂产品同一款号的新图片要在审核里「通过并替换图片」或「保留原图」。
2. 打开「人工审核」：左侧选图，中间查看完整图片和来源，右侧对照 AI 建议调整标签。
3. 填写审核人姓名，选择「直接通过」「修改后通过」或「驳回」。驳回必须填写原因。
4. 通过后主页标记为「已审核」。未审核图片可在主页浏览，也可在搜索中勾选「包含未审核图片」；已驳回图片不出现在主页或任何搜索结果中。
5. 在「已通过」「已驳回」中查看处理记录，必要时「重新提交审核」。重新审核期间图片仍在主页，按本轮待审核分类展示并标记「未审核」。

AI 全量重打标和重复导入都会生成新的待审核建议，保留此前人工确认的标签。再次通过才会替换最终分类。每次新建议、通过、驳回、重新提交都会保存前后快照，历史面板可追溯标签、审核人、时间和意见。

## 存储与迁移

首次切换前先停止旧应用，备份 `data/`，再启动新版本，避免旧 JSON 写入程序与 SQLite 版本同时处理同一份资料。

- `data/processed/catalog.sqlite3`：图片记录、审核状态和追加保存的操作历史。SQLite 来自 Python 标准库，无需另装数据库服务。
- `data/raw/`、`data/extracted/`：原始资料和图片。
- `data/processed/index/`：FAISS 检索索引，只含已审核通过的图片；图片搜索时会自动校正索引成员，无需每次审批后手动重建。
- 首次访问数据库时，自动、事务性地导入现有 `catalog.json`，保留原 JSON 文件且只导入一次。历史记录全部标记为待审核，即使以前做过人工修改，也不会自动视为审核通过。
- 主页支持全部 / 未审核 / 已审核筛选；API 使用 `review_status=pending|approved`。`display_tags` 提供当前展示分类，筛选也使用同一分类，不改写保存的人工结果。新后台导入保存上传时间 `source.uploaded_at`；历史记录没有该字段时显示原抽取时间 `source.extracted_at`，审核或重新打标不改变这一时间。
- `tags` 保留当前或上次人工结果；`ai_tags` 是最新模型建议；`proposed_tags` 是本轮待审核分类。历史快照保存历轮建议和决定。
- 每条记录都有版本号。审核或写入旧版本返回 HTTP 409，刷新后重新确认，避免并发操作静默覆盖。
- API 通过记录 ID 提供图片，不再公开整个 `data/` 目录，因此不会公开数据库和原始办公文档。

备份时停止应用，再复制整个 `data/` 目录。SQLite WAL 模式下不要在运行期间单独复制数据库主文件；可用 SQLite backup API 制作在线备份。

本期是一级审核，审核人姓名由操作人员填写，尚未接登录账号和角色权限。适合受信任的内部环境，不提供身份认证的审计保证。

## 启动与验证

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn api.main:app --host 127.0.0.1 --port 8520
# 另开终端
cd frontend
npm ci
npm run dev
```

打开 http://127.0.0.1:8518/review。无 API Key 时可选择 Mock 验证导入和审核流程；Mock 不代表真实 AI 分类效果。CLIP 不可用时会降级，文字搜索仅使用标签匹配。

```bash
.venv/bin/python -m pytest -q
cd frontend
npm run build
```

可用 `CLOTHEXTRACT_DATA_DIR=/absolute/path` 指定独立数据目录。测试通过临时目录运行，不修改真实图库，也不调用付费 AI 接口。

旧 `/edit` 地址自动跳转到 `/review`。

默认端口被占用时，可指定独立端口（不要把测试资料导入已有服务）：

```bash
CLOTHEXTRACT_DATA_DIR=/tmp/clothextract-demo EMBEDDING_BACKEND=local .venv/bin/python -m uvicorn api.main:app --host 127.0.0.1 --port 18520
# 在 frontend 目录另开终端
API_PROXY_TARGET=http://127.0.0.1:18520 npm run dev -- --host 127.0.0.1 --port 18518 --strictPort
```

长期使用自定义 API 端口时，可在 `frontend/.env.local` 中保存 `API_PROXY_TARGET=http://127.0.0.1:18520`。Vite 启动和配置重载都会读取该文件；命令行环境变量优先。本地配置已被 Git 忽略，不会提交到仓库。前端显示 Bad Gateway 时，先确认此代理地址与实际 API 监听端口一致。

## 导入任务、审核提效与款式详情

导入页现使用后台任务：文件上传成功后返回任务编号，页面显示抽图 / 打标阶段、文件和图片计数、成功 / 失败数量、耗时与估算剩余时间。可切换页面；任务完成或出现异常时显示站内提示。拖拽与文件选择均支持多文件上传。

任务和逐图检查点存入同一 SQLite 数据库。每张分类结果与任务检查点在一个事务中提交，重试跳过已完成图片。网络故障、余额不足和鉴权失败显示可操作的错误说明，不向页面返回原始上游错误或密钥。因额度或鉴权失败会提前停止继续请求。明确点击重试后才继续；服务重启把未完成任务标记为中断，不会自行重复调用付费接口。

运行方式保持 **单个 Uvicorn 进程**，一个后台线程顺序处理任务，避免重复消费同一任务。不使用多进程 `--workers`。停止服务时等待正在执行的请求正常结束；如发生强制中断，可在任务记录中继续未完成项。导入与全量重新分类均提供后台任务接口，旧同步接口保留供现有脚本兼容使用。

任务记录显示本次更新后新建的任务；此前已导入的资料仍保留在图库和「历史导入」筛选中。任务记录默认展示最近 50 批。

审核页可按导入批次、来源文件、服装品类筛选，并将状态、分页及选中图片保存到 URL。支持上一张 / 下一张、暂时跳过；`←` / `→` 切图、`A` 通过、`S` 跳过，在输入框内不触发快捷操作。跳过仍保持待审核。未提交的分类或意见在切图、离开、刷新前会提醒。

从图库、检索结果和审核页可进入 `/records/:id` 款式详情：查看完整原图、AI 与人工标签对照、来源文件及位置、审核历史，下载原图和存在的来源资料，或发起以该款为参考的相似款检索。相似款排除参考图自身，可选择是否包含未审核款式。

导入任务接口：

- `POST /api/import/jobs`：上传并启动任务（202）。
- `GET /api/import/jobs` 与 `GET /api/import/jobs/{id}`：查看进度。
- `POST /api/import/jobs/{id}/retry`：继续未完成项（202）。
- `POST /api/tag/jobs`：后台补打 / 全量重新分类（202）。

正式使用应设置固定持久化目录 `CLOTHEXTRACT_DATA_DIR`。备份须包含原始资料、抽取图片和数据库；不要只保留 Git 仓库。已有 SQLite 图库迁移目录前，先正常停止服务，用 SQLite backup API 备份，核对记录、审核历史和图片完整性后再启动。

## 图片清晰度

PDF 抽图按嵌入图片的像素密度渲染，保留页面上的旋转、透明蒙版和分片合成；不再将渲染倍率限制为 4 倍。输出使用无损 PNG。单张区域超过 2000 万像素或最长边 8192 像素时按比例限制，以控制内存；源文件自身的模糊无法通过抽取恢复。PPT / Excel 中无需纠正 EXIF 朝向的 JPEG、PNG 等图片直接保留原始字节，避免二次有损压缩。

列表与审核队列使用最长 480 × 640 的独立缩略图，不放大低分辨率原图；详情、完整原图和下载提供原始尺寸。图片 URL 带文件版本，刷新图片后不会继续命中旧版浏览器缓存。缩略图保存在 `data/processed/thumbnails/`，可以删除并自动生成；详情显示实际像素尺寸。

恢复之前导入的低分辨率 PDF 图片：先停止 API，运行 `.venv/bin/python scripts/refresh_pdf_images.py` 检查，再加 `--apply` 执行。脚本按来源文件、页码和区域序号匹配，保留记录 ID、标签、图注、导入时间及人工审核状态；更新前在 `data/backups/image-quality-*/` 备份数据库、旧图片和索引。恢复会新增图片更新历史、清除旧检索索引（下次检索自动重建），不调用 AI 或产生打标费用。缺失来源或无法匹配的记录会列为跳过，不猜测对应关系。

## 本地灵感搜索

导航「灵感找款」支持风格、场景、颜色、材质与排除项，例如「秋日法式，奶油色，松弛感」「极简通勤的羊毛外套」「周末休闲，不要红色」。本地词汇表把常见表达映射为偏好；明确提到的品类、颜色和排除条件会限制候选，其他偏好用于排序；「只要」「必须」可将其他明确标签限定为条件。规则为近似映射，不会改写商品的标签。图片和已有款式说明参与匹配，不生成大模型推荐理由。

安装依赖后运行 `.venv/bin/python scripts/prepare_local_search.py --index`，首次从模型发布方下载 CLIP 图片模型和多语言文字模型（无需 API Key）。随后用 `EMBEDDING_BACKEND=clip` 启动 API。搜索时只读取本机权重、计算向量，不上传图片或调用 OpenAI / Hugging Face 推理 API。未准备好模型时回退到本地词汇匹配，页面如实显示当前检索方式；首次下载、模型加载或建立新图库索引可能较慢。

搜索页默认勾选「包含未审核图片」，结果卡片标明审核状态；可以关闭以仅搜索已审核款式。底层文字、图片、相似款 API 保持 `include_pending=false` 默认，显式传入 `true` 才扩大范围；已驳回和演示图始终从默认候选排除。待审核记录按当前建议分类检索，保留上次人工结果。已审核与包含未审核的索引分开保存，不能因切换范围泄漏记录。图片向量缓存跟踪文件像素版本，审核变化不会重复编码所有图片，替换图片后会自动重算。

搜索条件和审核范围保存在 URL 中，打开详情后返回、刷新或分享本地页面链接可以恢复文字搜索。上传参考图片在内存中保留，刷新页面后需要重新选择文件。
